# بالمفهوم | BELMAFHOOM

منصة تعليمية عربية مبنية بـ Next.js 15.5.29 وReact 19.0.7 وSupabase. هذه الحزمة هي تحديث موحّد لواجهة المشروع وقاعدة البيانات الحالية، وليست نشرًا عامًا للموقع.

## ما أصبح موجودًا في الواجهة

### اكتشاف المدرسين والمنصة العامة
- دليل عام للمدرسين المعتمدين مع صفحات تعريفية لكل مدرس تعرض النبذة والمواد والمراحل والكورسات المنشورة.
- بحث في دليل المدرسين بالاسم أو المادة أو الكورس، مع فلاتر المادة والمرحلة.
- البحث في الكورسات بالاسم والمادة والصف، مع فلتر للكورسات المجانية.
- صفحات تعريفية للمنصة ومركز مساعدة يوضح خطوات الاستخدام والدفع اليدوي وطلب ربط ولي الأمر.

### الحسابات والملفات الشخصية
- تسجيل الدخول والتسجيل كطالب أو مدرس أو ولي أمر، مع استعادة كلمة المرور وتعيين كلمة جديدة عبر رابط بريد آمن.
- حفظ الاسم ورقم الهاتف من بيانات التسجيل.
- صفحة ملف شخصي لتحديث بيانات الطالب التعليمية أو نبذة المدرس والمواد والمراحل التي يدرسها.
- لوحة تحكم منفصلة بحسب نوع الحساب، مع إشعارات داخلية.

### الكورسات والتعلّم
- الصفحة الرئيسية وفهرس الكورسات يقرآن الكورسات المنشورة من Supabase، من دون بيانات مدرسين أو كورسات تجريبية ثابتة.
- صفحة تفاصيل لكل كورس.
- الطالب يطلب الاشتراك؛ المجاني يتفعل وفق Trigger قاعدة البيانات، والمدفوع يظل معلقًا حتى مراجعة المدرس أو الإدارة.
- رفع إيصال تحويل للطالب PDF أو JPG أو PNG أو WEBP، بحد أقصى 50MB.
- المدرس ينشئ كورسًا ويعدّل بياناته، ويضيف وحدات ودروسًا نصية أو ملفات أو روابط YouTube/Vimeo، ثم ينشر بعد استيفاء شروط الاعتماد.
- ملفات الدروس وإيصالات الدفع والتسليم محفوظة في Bucket خاص، وتُفتح بروابط موقعة قصيرة العمر بعد فحص صلاحية Storage/RLS.
- الطالب المشترك يصل إلى صفحة التعلّم، والدروس المجانية المعاينة متاحة وفق سياسة قاعدة البيانات.
- الطالب يحدد الدروس المكتملة، وتظهر نسبة التقدم في الكورس، ويستطيع ولي الأمر رؤية عدد الدروس المكتملة بعد موافقة الطالب.

### الواجبات والامتحانات
- المدرس ينشئ واجبات كمسودات ثم ينشرها.
- الطالب يسلّم إجابة نصية أو ملفًا، ويمكنه إعادة التسليم إذا أعاد المدرس الواجب للمراجعة.
- المدرس يراجع التسليم ويضيف الدرجة والملاحظات.
- المدرس ينشئ امتحانات اختيار من متعدد، ويضيف الأسئلة والاختيارات والإجابة الصحيحة، ثم ينشر.
- الطالب يبدأ محاولة بوقت وعدد محاولات محددين من قاعدة البيانات، ويحفظ إجاباته، ويظهر له عدّاد تنازلي؛ عند انتهاء الوقت تُرسل المحاولة تلقائيًا. صلاحية حفظ الإجابة تنتهي أيضًا من قاعدة البيانات عند انتهاء الوقت.
- تصحيح الاختيارات آليًا. بيانات الدرجات لا تُمنح صلاحية قراءتها مباشرة من جدول المحاولات للطالب؛ تُعرض عبر دالة تتحقق من إعداد إظهار النتيجة، بينما يستطيع المدرس مراجعة نتائج طلابه.

### أولياء الأمور والإدارة
- ولي الأمر يرسل طلب ربط باستخدام رقم حساب الطالب.
- الطالب يوافق صراحة قبل مشاركة بياناته التعليمية، ويمكنه رفض الطلب أو إلغاء الربط لاحقًا.
- ولي الأمر يرى بيانات المرحلة والصف والمدينة والاشتراكات وعدد الدروس المكتملة بعد الموافقة فقط.\n- لوحة الطالب تعرض ملخصًا للاشتراكات والواجبات، ولا تعرض الواجبات إلا من الكورسات ذات الاشتراك النشط.
- لوحة الإدارة تراجع اعتماد المدرسين، وطلبات اشتراك الكورسات، واشتراكات المدرسين، وتضيف أو توقف باقات المنصة، وتعرض مؤشرات إجمالية وإدارة آخر 50 حسابًا مع إيقاف الحساب أو إعادة تفعيله (من دون تغيير الأدوار).
- اشتراك المدرس يدوي بتحويل وإيصال؛ الإدارة تحدد مدة التفعيل عند القبول.

### قابلية التثبيت
- تمت إضافة Web App Manifest وأيقونة أساسية لتسهيل إضافة الموقع للشاشة الرئيسية كتطبيق ويب.

## تغييرات قاعدة البيانات التي طُبقت
تم تطبيق التغييرات الإضافية على مشروع Supabase الحالي `ertbyybmzizpdcaehhkw`:
- جدول `guardian_consents` لتوثيق موافقة الطالب على ربط ولي الأمر.
- جدول `lesson_progress` لتسجيل إنجاز الدروس مع صلاحيات للطالب والمدرس وولي الأمر المرتبط.\n- جدول `public_teacher_directory` منفصل ومحدود الحقول لعرض المدرسين المعتمدين النشطين للعامة، ويُحدّث تلقائيًا عبر triggers؛ لا يحتوي على أرقام الهواتف أو بيانات الطلاب.
- Trigger يفرض موافقة الطالب قبل تفعيل الربط، ويسمح له بإلغاء الربط.
- سياسات RLS تسمح للإدارة الموثوقة بمراجعة المدرسين، وتسمح لولي الأمر برؤية بيانات الطالب التعليمية بعد الربط النشط فقط.
- دمج سياسات القراءة والتحديث بدل ترك سياسات permissive إضافية متكررة.
- فهارس لعلاقات موافقات أولياء الأمور، وفهرس يمنع تكرار طلب ربط نشط بين نفس الطرفين.

ملفات التغييرات: `supabase/changes/2026-11-21-secure-public-teacher-directory.sql`، `supabase/changes/2026-11-21-guardian-consent-and-admin-access.sql`، بالإضافة إلى ملفات التحصين المتتابعة بتاريخ 2026-11-21 في مجلد `supabase/changes/`.
تحديث تشديد الصلاحيات: `supabase/changes/2026-11-21-privilege-hardening.sql` (تم تطبيقه على المشروع الحالي).
- حواجز تحديث الحقول الحساسة: `supabase/changes/2026-11-21-sensitive-update-guards.sql`، مع تصحيح التوافق في `supabase/changes/2026-11-21-preserve-assignment-submission-guard.sql`، ثم `supabase/changes/2026-11-21-allow-trusted-db-maintenance.sql`؛ تمنع ترقية الدور أو اعتماد المدرس ذاتيًا، وتمنع الطالب من تفعيل اشتراكه أو المدرس من تفعيل اشتراك منصته بنفسه. حارس تسليم الواجبات الأصلي يظل مسؤولًا عن منع الطالب من تصحيح واجبه بنفسه.

لا تشغّل migration القديمة داخل `legacy/` على قاعدة البيانات الحالية؛ فهي نسخة تأسيسية سابقة ولا تطابق المخطط الحالي.

## إصدارات الاعتماديات
- Next.js و`eslint-config-next`: `15.5.29` (تحديث أمني لفرع 15.x).
- React وReact DOM: `19.0.7`.
- إصدارات الحزم مثبتة في `package.json`. لم يتم إنشاء `package-lock.json` لأن اتصال npm registry تعذر أثناء إعداد الحزمة؛ أنشئ lockfile بعد نجاح `npm install` واحتفظ به مع المشروع قبل النشر.

## التشغيل

1. استخدم Node.js 20 أو أحدث.
2. انسخ `.env.example` إلى `.env.local`.
3. ضع عنوان Supabase ومفتاح `anon` أو `publishable` العام في المتغيرات.
4. أضف عنوان callback الخاص بموقعك إلى Supabase Auth Redirect URLs:
   `https://YOUR-DOMAIN/auth/callback` (ويُستخدم المسار نفسه لاستعادة كلمة المرور مع `?next=/reset-password`)
5. نفّذ:
   ```bash
   npm install
   npm run dev
   ```
6. افتح `http://localhost:3000`.

المتغيرات:
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `NEXT_PUBLIC_SITE_URL`

لا تضف `service_role` أو Secret Key إلى المتصفح أو إلى أي متغير يبدأ بـ `NEXT_PUBLIC_`.

## إعداد الإدارة

لا يوجد تسجيل عام كمدير، ولا توجد آلية داخل الموقع لترقية المستخدم لنفسه. صلاحية الإدارة تعتمد على `app_metadata.role = admin` في Supabase Auth، بالإضافة إلى دور `admin` في سجل `profiles`. يتم التحقق من الشرطين داخل الصفحة وكل إجراء إداري على الخادم، وليس بمجرد إخفاء الواجهة. يجب تعيين أول مدير من قناة موثوقة خارج الموقع بواسطة مالك المشروع، ثم تسجيل الخروج والدخول لتحديث JWT. لا تستخدم `user_metadata` لتحديد صلاحيات الإدارة.

## تكاملات لم تُفعّل بعد

- فيديوهات YouTube/Vimeo العامة تعمل كرابط تضمين. حماية الفيديوهات المدفوعة ومنع تنزيلها تحتاج ربط Cloudflare Stream أو مزود فيديو خاص ومفاتيح حسابه.
- لا توجد بوابة دفع إلكتروني بعد؛ الدفع الحالي تحويل يدوي للمدرس أو لإدارة المنصة.
- الإشعارات الحالية داخل قاعدة البيانات ولوحة التحكم؛ لا توجد Web Push أو رسائل SMS/WhatsApp أو بريد آلي بعد.
- لا توجد غرفة بث مباشر مدمجة؛ نوع درس البث المباشر حاليًا يعرض تعليمات أو رابطًا نصيًا.
- الموقع قابل للتثبيت كتطبيق ويب، لكن لم يتم بناء تطبيق Android/iOS أصلي.
- المشروع مربوط باستضافة Vercel على النطاق الفرعي `belmafhoom.vercel.app`؛ لم يتم ربط دومين مخصص أو Cloudflare حتى الآن.

## الاختبارات والحدود

- تم فحص تركيب ملفات TypeScript/TSX في التحديث الأخير: 34 ملفًا، دون أخطاء syntax.
- تم التحقق من صلاحيات أعمدة درجات الامتحان: دور `authenticated` لا يستطيع قراءة `score` أو `max_score` أو `percentage` مباشرة، ويستخدم التطبيق دالة `get_exam_attempt_result` التي تتحقق من هوية الطالب وإعداد إظهار النتيجة.
- أضيف مؤقت تنازلي للامتحان مع إرسال تلقائي عند انتهاء الوقت، مع بقاء فرض انتهاء الوقت وحفظ الإجابات من جهة قاعدة البيانات.
- فحص Supabase Security Advisor وHealth Advisor بعد آخر تغييرات قاعدة البيانات: لا توجد تحذيرات ظاهرة.
- اختبارات قاعدة بيانات rollback-only أثبتت نجاح دورة طلب ولي الأمر وموافقة الطالب وتفعيل الربط وإلغائه ثم إعادة الطلب، كما أثبتت إمكانية إعداد أول مدير وإنشاء باقات المدرسين من جلسة الإدارة.
- اختبار امتحان تجريبي داخل معاملة rollback أثبت أن طلب بدء الامتحان مرتين يعيد المحاولة المفتوحة نفسها ولا يستهلك محاولة إضافية.
- تم فحص صلاحيات الجداول: كل الجداول العامة الـ25 مفعّل عليها RLS؛ الطالب/المدرس لا يستطيعان تعديل جدول محاولات الامتحان مباشرة، والقراءة متاحة فقط وفق سياسات المالك/المدرس.
- تشديد صلاحيات الجداول الحالية: إزالة `TRUNCATE` و`TRIGGER` و`REFERENCES` من `anon` و`authenticated`، وإلغاء إمكانية استدعاء دالة إنشاء الحساب كـ RPC، وقصر دوال الامتحانات على المستخدم المسجل. تم التحقق من الصلاحيات بعد التطبيق.
- فحص الأداء الحالي أظهر 32 ملاحظة معلوماتية عن فهارس غير مستخدمة (طبيعي قبل وجود استخدام فعلي وحركة مرور كافية)؛ لم تُحذف الفهارس لأنها تخدم استعلامات متوقعة عند التشغيل.
- لم يكتمل `npm install` في بيئة العمل بسبب فشل DNS عند الوصول إلى `registry.npmjs.org`؛ لذلك لم يتم تشغيل `next build` أو ESLint أو اختبار متصفح فعلي، ولم يُنشأ `package-lock.json`.
- لم تُختبر التدفقات بحسابات حقيقية لطالب ومدرس وولي أمر ومدير، ولم يتم نشر الموقع.
- يلزم اختبار التسجيل وتفعيل المدرس ورفع الملفات والاشتراك وتسليم الواجب والامتحان من جلسات حقيقية قبل فتح المنصة للطلاب.
- يلزم مراجعة قانونية وخصوصية منفصلة قبل التعامل مع بيانات القاصرين، وتحديد سياسة حذف البيانات والاحتفاظ بها.

كل عمليات الوصول إلى Supabase تتم بجلسة المستخدم وسياسات RLS. لا يوجد مفتاح خدمة داخل كود المتصفح.
